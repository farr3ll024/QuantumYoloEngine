# QuantumYoloEngine — web

Browser-based BTC/ETH paper-trading simulator. Vite + React + TypeScript, strict mode. The entire
simulation runs client-side in a Web Worker (`src/worker/simulation.worker.ts`); there is no
backend and no exchange connection.

> Experimental software for education and paper trading only. It does not place live trades and is
> not financial advice. Backtests and simulated results do not predict future performance.

## Development

```bash
npm ci
npm run dev
```

## Quality gate

```bash
npm run lint         # eslint . (includes eslint-plugin-jsx-a11y)
npm run typecheck    # tsc -b --pretty false, strict mode
npm test             # vitest run (unit tests + cross-engine parity against tests/parity/fixtures)
npm run build         # tsc -b && vite build
npm run test:e2e     # playwright test (chromium + a mobile viewport project)
```

## Structure

- `src/engine/` — pure, dependency-light simulation engine: `model.ts` (types), `validate.ts`
  (strategy validation), `simulate.ts` (the state machine, a direct port of
  `quantum_yolo_engine/engine.py`), `metrics.ts` (event-sourced equity/drawdown), `strategy.ts`
  (YAML import/export + sha256 hashing), `reports.ts` (ZIP report export).
- `src/worker/simulation.worker.ts` — runs the engine off the main thread with start/pause/
  resume/step/cancel/reset controls.
- `src/storage/db.ts` — IndexedDB persistence (strategies, runs, preferences) via `idb`.
- `src/data/csv.ts` — CSV dataset import/validation.
- `src/routes/` — `/`, `/simulator`, `/runs`, `/compare`, `/methodology`, `/privacy`.
- `tests/unit/` — Vitest, including `parity.test.ts`, which loads every fixture in
  `../../tests/parity/fixtures/*.json` (generated by the Python reference engine) and asserts this
  engine reproduces them exactly.
- `tests/e2e/` — Playwright: route smoke tests, the simulator happy path, pause/resume/reset,
  keyboard workflow, and a 320px-width overflow check.

## Behavioral parity with the Python reference engine

`src/engine/simulate.ts` and `src/engine/metrics.ts` must reproduce the exact fill/equity/drawdown
behavior of `quantum_yolo_engine/engine.py` and `quantum_yolo_engine/metrics.py`. The contract is
enforced by `tests/unit/parity.test.ts` against fixtures in `../tests/parity/fixtures/`, generated
by `tests/parity/generate_fixtures.py`. If you change fill logic on either side, regenerate the
fixtures and make sure both test suites pass.
